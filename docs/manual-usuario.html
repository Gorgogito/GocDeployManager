GocDeployManager

Guía paso a paso para configurar el sistema y realizar despliegues de GOCs hacia SIT, IDI y ProPag — pensada para usarse mientras trabajás con la aplicación abierta al lado.

01 Qué es GocDeployManager

Reemplaza el proceso manual de clonar una rama, compilar por capas con MSBuild y copiar los binarios a mano.

Cada corrección o mejora que se despliega tiene un número de GOC (por ejemplo GOC-19205). GocDeployManager toma ese número, clona automáticamente la rama correspondiente desde Bitbucket, compila el sistema en el orden correcto, y copia el resultado al ambiente que elijas — sin que tengas que acordarte de ningún paso ni de qué archivo no hay que pisar.

Todo despliegue, salga bien o mal, queda registrado en el Historial con fecha, usuario, duración y motivo de fallo si lo hubo.

Antes de empezar Necesitás que tu máquina tenga acceso real a Bitbucket, a MSBuild y a la ruta de red del ambiente donde vas a desplegar. GocDeployManager no reemplaza esos accesos, solo automatiza los pasos una vez que existen.

02 Primeros pasos

La primera vez que se abre la aplicación en una base de datos vacía, la pantalla de inicio de sesión se convierte en el alta del primer administrador.

2.1Crear el administrador

Al abrir GocDeployManager por primera vez (sin ningún usuario todavía registrado), vas a ver esta pantalla en vez del login normal:

  1. Usuario — el nombre con el que vas a iniciar sesión de ahora en más (por ejemplo jtorres). No se puede cambiar después.
  2. Nombre visible — tu nombre completo, es lo que se muestra en el título de la pantalla principal.
  3. Contraseña y Confirmar contraseña — deben coincidir exactamente.
  4. Hacé clic en Crear y continuar.

El usuario que acabás de crear queda con rol Administrador automáticamente: puede entrar a Configuración, dar de alta más usuarios y hacer despliegues.

2.2Iniciar sesión

De acá en más, cada vez que abras la aplicación vas a ver la pantalla normal de inicio de sesión, con tu usuario ya recordado del paso anterior:

Si te equivocás de contraseña El mensaje de error es siempre el mismo ("Usuario o contraseña incorrectos"), sin importar si el que falló fue el usuario o la contraseña — es intencional, para no darle pistas a quien intenta adivinar credenciales ajenas.

03 Roles de usuario

Cada usuario tiene exactamente uno de estos 3 roles, asignado por un Administrador.

RolPuede desplegarPuede entrar a ConfiguraciónPuede ver el Historial
AdministradorSíSíSí
OperadorSíNoSí
ConsultaNoNoSí

Si iniciás sesión con un rol que no puede desplegar, el botón "Iniciar despliegue" aparece deshabilitado con el texto "Sin permiso". Si intentás entrar a Configuración sin ser Administrador, aparece un aviso y no se abre la pantalla.

04 Configuración inicial

Solo un Administrador puede entrar acá — se accede desde "Configuración" en el menú de la izquierda de la pantalla principal. Tiene 4 pestañas.

4.1Ambientes

Un ambiente (Desarrollo, Testing, Producción...) define, para cada sistema que soporta, a qué ruta de red se copian los archivos compilados. Un mismo ambiente puede soportar uno o varios sistemas (SIT, IDI, ProPag).

  1. Nuevo — crea un ambiente vacío en el panel de la derecha.
  2. Escribí el nombre del ambiente y hacé doble clic sobre "Sistemas" para agregar uno o más: cada sistema necesita su código (debe coincidir con el configurado en la pestaña Bitbucket), un nombre visible, y la ruta destino real (por ejemplo una ruta de red \\Servidor\Aplicaciones\SIT).
  3. Guardar — valida que el nombre y al menos un sistema estén completos antes de escribir el archivo de configuración.
  4. Eliminar — pide confirmación antes de borrar el ambiente seleccionado.

4.2Sistemas y Bitbucket

Acá se configura, por cada sistema (SIT, IDI, ProPag...), de dónde se clona el código y cómo se compila. Cada sistema es un repositorio Bitbucket distinto — no comparten código fuente aunque a veces compartan nombres de proyecto internos.

Código de sistema

Identificador corto (SIT, IDI, PROPAG). Es el mismo código que usás en la pestaña Ambientes.

URL del repositorio Bitbucket

La dirección del repositorio Git de ese sistema — el que se clona en cada despliegue.

Carpeta precompilada

La carpeta, dentro del repositorio ya compilado, cuyo contenido es lo que realmente se copia al ambiente destino.

Pasos de build

La secuencia de carpetas que se compilan en orden con MSBuild — el mismo orden que hoy exige compilar a mano.

Importante El orden de los pasos de build no es arbitrario: cada capa depende de que la anterior ya esté compilada. Si no estás seguro del orden correcto para un sistema nuevo, consultá el script de compilación manual que se usaba antes — el orden debe ser idéntico.

4.3Usuarios

Alta de usuarios, cambio de rol, activar/desactivar cuentas, resetear contraseñas y configurar las credenciales personales de Bitbucket de cada uno.

Para dar de alta un usuario nuevo, hacé clic en Nuevo usuario:

Un usuario no puede desplegar sin esto Si tu usuario de aplicación no tiene credenciales de Bitbucket configuradas, la pantalla principal va a rechazar cualquier intento de despliegue con el mensaje "Tu usuario no tiene credenciales de Bitbucket configuradas." Pedile a un Administrador que te las configure la primera vez.

4.4Rutas generales

Las carpetas de trabajo que usa la aplicación: dónde clona el código, dónde deja archivos temporales, dónde escribe los logs, dónde guarda los archivos de configuración (Ambientes, Sistemas) y la cadena de conexión a la base de datos SQL Server donde viven los usuarios y el historial.

La base debe existir antes de usar la app A diferencia de las carpetas (que la app crea sola si no existen), la base de datos SQL Server debe estar creada de antemano: alguien con permisos tiene que ejecutar una vez el script sql/schema-sql-server.sql contra ella (con SQL Server Management Studio o sqlcmd). Si la cadena de conexión apunta a una base sin ese script aplicado, la aplicación no arranca y muestra un mensaje indicándolo.
Reiniciar después de guardar Los cambios en esta pestaña se guardan de verdad, pero recién se aplican la próxima vez que abras la aplicación — no hay reinicio en caliente. La propia pantalla te avisa esto al guardar.

05 Realizar un despliegue

Esta es la tarea del día a día — la pantalla principal, la que ves apenas iniciás sesión.

  1. Ingresá el número de GOC — formato exacto GOC-00000 (5 dígitos). GocDeployManager arma solo el nombre de la rama a partir de este número.
  2. Elegí el ambiente — el combo se llena con los ambientes que un Administrador configuró. Al elegir uno, aparecen abajo los sistemas que ese ambiente soporta.
  3. Marcá los sistemas a desplegar — vienen todos tildados por defecto, destildá los que no correspondan a este GOC.
  4. Hacé clic en "Iniciar despliegue".

Mientras corre, la pantalla queda bloqueada (no se admite cancelar ni disparar dos despliegues a la vez) y el panel de progreso muestra en vivo cada paso: clonado, cada capa de compilación, y la copia final de archivos.

Si falla La notificación te muestra el motivo exacto (rama no encontrada, error de compilación, archivo bloqueado, etc.) y el despliegue queda registrado igual en el Historial como fallido, con ese mismo motivo — no se pierde el rastro de qué pasó.
No se puede cancelar Una vez que hacés clic en "Iniciar despliegue", corre hasta el final (éxito o fallo) — no hay botón para cancelarlo a mitad de camino. Confirmá el GOC, el ambiente y los sistemas antes de arrancar.

06 Consultar el historial

Todos los despliegues quedan acá — exitosos y fallidos. Se abre desde "Historial" en el menú de la izquierda.

  • Filtrar — completá cualquier combinación de campos y hacé clic en "Buscar"; "Limpiar" vuelve a mostrar todo.
  • Ver detalle — seleccioná una fila y hacé clic acá (o doble clic sobre la fila) para ver todos los datos del despliegue, incluyendo el usuario de Windows y el equipo desde el que se ejecutó.
  • Exportar a Excel / Exportar a PDF — exporta exactamente lo que ves filtrado en la grilla en ese momento.

07 Preguntas frecuentes

"Usuario o contraseña incorrectos" y estoy seguro de que están bien

Revisá mayúsculas/minúsculas y que no haya un espacio de más al final del usuario. El mensaje es siempre el mismo por seguridad, no distingue cuál de los dos campos falló.

Olvidé mi contraseña y soy el único usuario

Hoy el reseteo de contraseña lo hace otro Administrador desde la pestaña Usuarios — está pensado para cuando hay más de una persona con ese rol. Si sos el único usuario registrado y olvidaste tu contraseña, contactá al equipo de soporte técnico: es una situación que requiere una intervención puntual sobre la instalación, no algo que se resuelva desde la pantalla de login.

"Tu usuario no tiene credenciales de Bitbucket configuradas"

Pedile a un Administrador que te las configure desde Configuración › Usuarios › Configurar credenciales Bitbucket. Son tus credenciales personales, no las de la aplicación en general.

El GOC me lo rechaza como formato inválido

Tiene que ser exactamente GOC- seguido de 5 dígitos, por ejemplo GOC-19205. No hace falta escribir el nombre completo de la rama — la aplicación arma feature/GOC-19205 sola.

"No tiene configurada una ruta para [sistema]"

El ambiente que elegiste no incluye ese sistema. Un Administrador tiene que agregarlo desde Configuración › Ambientes, con la ruta de red destino correspondiente.

El despliegue falló compilando una capa

El motivo exacto queda en el log de la pantalla principal y en el detalle del Historial. Casi siempre es un problema real de compilación (código con errores en esa rama) — verificalo igual que lo harías compilando esa capa a mano.

Solo un administrador puede acceder a Configuración

Es por diseño: los roles Operador y Consulta pueden desplegar (Operador) o solo mirar el Historial (Consulta), pero no tocar Ambientes, Bitbucket, Usuarios ni rutas generales.
