Introducción

Qué es GocDeployManager y para qué sirve

GocDeployManager es una herramienta de escritorio desarrollada en WPF (.NET 4.8) para automatizar y gestionar el proceso de despliegue de GOCs (ramas de trabajo en Bitbucket) hacia los distintos ambientes de prueba y producción del equipo.

Con ella, cada integrante puede seleccionar un GOC, elegir los ambientes destino, y lanzar el proceso de despliegue de forma controlada, con registro de historial centralizado y gestión de usuarios.

Conceptos clave

TérminoDescripción
GOCRama de trabajo en Bitbucket identificada por un código (ej. GOC-19205). Contiene los cambios listos para desplegar.
AmbienteEntorno de destino: conjunto de sistemas con sus rutas de servidor (ej. Ambiente JTorres). Cada usuario puede tener el suyo propio.
SistemaProyecto dentro de un ambiente (ej. SIT, IDI, PROVPAG). Define URL Bitbucket, ruta de precompilado y pasos de compilación.
DespliegueProceso completo: clonar el GOC, compilarlo y copiar los artefactos al servidor del ambiente destino.

Requisitos del sistema

Requisitos técnicos

  • 🖥 Windows 10 / Windows 11
  • ⚙ .NET Framework 4.8
  • 🗃 SQL Server 2019 o superior
  • 📁 Git instalado en el sistema
  • 🌐 Acceso a la red corporativa

Accesos necesarios

  • 🔑 Credenciales Bitbucket corporativas
  • 🗃 Acceso a BD GocDeployManager
  • 📁 Permisos en rutas de despliegue
  • 👤 Cuenta activa en la aplicación
💡

Inicio de sesión

Cómo acceder al sistema

Pantalla de inicio de sesión en tema oscuro — campos Usuario y Contraseña con botón INGRESAR

2.1 Primer arranque — Crear contraseña inicial

La primera vez que accedes con tu usuario, el sistema detecta que no tienes contraseña configurada y te guía para crearla. Este proceso ocurre una sola vez.

  1. Abre GocDeployManager.UI.exe. Aparece la pantalla de inicio de sesión.
  2. Escribe tu usuario corporativo en el campo Usuario (ej. JTorres) y presiona Enter o haz clic en INGRESAR.
  3. El sistema muestra el campo Nombre visible. Escribe el nombre que aparecerá en la app (ej. Jorge Torres) y presiona Enter.
  4. Aparece el campo de contraseña. Escribe tu contraseña nueva (mínimo 6 caracteres) y presiona Enter o haz clic en INGRESAR.
  5. El sistema crea tu cuenta y te lleva directamente a la ventana principal.
⚠️
ContraseñaGuarda tu contraseña en un lugar seguro. Si la olvidas, un administrador deberá restablecerla desde Configuración → Usuarios.

2.2 Inicio de sesión normal

Una vez que ya tienes cuenta configurada, el acceso es directo:

  1. Abre la aplicación. Se muestra la pantalla con los campos Usuario y Contraseña.
  2. Escribe tu usuario y presiona Enter para pasar al campo de contraseña.
  3. Escribe tu contraseña y presiona Enter (o haz clic en INGRESAR).
  4. Si las credenciales son correctas, accedes a la ventana principal.
⌨
Navegación con tecladoUsa Enter para avanzar de campo en campo sin el ratón: Usuario → Contraseña → INGRESAR. El ícono 👁 en el campo de contraseña permite mostrarla u ocultarla.

Realizar un despliegue

Proceso paso a paso para desplegar un GOC

Un despliegue toma el código de un GOC (rama de Bitbucket), lo compila y lo envía al servidor del ambiente destino. Sigue estos pasos:

  1. Ingresa el código del GOC
    Escribe el identificador en el campo principal, ej. GOC-19205. Es la rama de Bitbucket con los cambios a desplegar.
  2. Selecciona el ambiente
    Usa el selector desplegable para elegir el ambiente destino (ej. Ambiente JTorres).
  3. Elige los sistemas a desplegar
    Marca uno o varios checkboxes: SIT, IDI, Provisión Pagos, etc.
  4. Haz clic en INICIAR DESPLIEGUE
    El proceso comienza. El panel de estado muestra en tiempo real: clonado, compilación, copia de artefactos.
  5. Espera el resultado
    Al finalizar, el panel indica si fue exitoso o si hubo error. El resultado se registra automáticamente en el Historial.
⚠️
Durante el despliegueNo cierres la aplicación mientras el proceso está en curso. Hacerlo puede dejar el ambiente en estado inconsistente.
💡
Despliegue múltiplePuedes marcar varios sistemas a la vez. El proceso los desplegará secuencialmente en una sola ejecución.

La tabla muestra para cada usuario: código de login, nombre visible, rol, estado activo y email Bitbucket configurado. Las acciones del panel derecho son:

AcciónDescripción
Guardar rolCambia el rol del usuario (Administrador / Estándar).
DesactivarDeshabilita la cuenta sin eliminarla; el usuario no podrá iniciar sesión.
Resetear contraseñaEl usuario deberá crear una nueva contraseña en su próximo acceso.

Historial de despliegues

Registro centralizado de toda la actividad

El Historial registra automáticamente cada despliegue: quién lo ejecutó, cuándo, qué GOC, a qué ambiente, y si fue exitoso o fallido. Es el punto de referencia para auditoría y diagnóstico.

Historial de despliegues — Tabla de registros con fecha, GOC, ambiente, estado y usuario responsable

Columnas del historial

ColumnaDescripción
FechaFecha y hora en que se inició el despliegue.
GOCCódigo del GOC desplegado (ej. GOC-25...).
AmbienteSistema y ambiente destino del despliegue (ej. SIT).
EstadoExitoso o Fallido.
UsuarioCódigo del usuario que realizó el despliegue.

Cómo acceder

  1. En la ventana principal, haz clic en el ícono 📋 Historial de la barra lateral.
  2. Se abrirá la ventana GocDeployManager — Historial de despliegues con todos los registros.
  3. Desplázate por la tabla para revisar despliegues anteriores.
🔍
Diagnóstico de erroresSi un despliegue figura como Fallido, consulta los archivos de log en la ruta configurada en General para identificar la causa exacta del error.

Preguntas frecuentes

Respuestas a los problemas más comunes

¿Qué hago si olvidé mi contraseña?
Contacta a un administrador para que restablezca tu contraseña desde Configuración → Usuarios → Resetear contraseña. En tu próximo acceso el sistema te pedirá crear una nueva.
El despliegue falló — ¿qué debo revisar?
  1. Verifica que el código del GOC sea correcto y que la rama exista en Bitbucket.
  2. Confirma que tus credenciales Bitbucket estén configuradas en Configuración → Usuarios → Configurar credenciales Bitbucket.
  3. Revisa los logs en la ruta indicada en Configuración → General → Ruta de logs.
  4. Verifica permisos de escritura en la ruta de despliegue del ambiente.
  5. Asegúrate de que el servidor SQL Server esté activo y accesible.
¿Por qué no veo el botón Configuración en la barra lateral?
El acceso a Configuración está restringido a cuentas con rol Administrador. Si necesitas acceso, solicita a un administrador que cambie tu rol desde Configuración → Usuarios → Guardar rol.
¿Puedo desplegar a varios sistemas al mismo tiempo?
Sí. Puedes seleccionar múltiples sistemas marcando sus checkboxes en la ventana principal (SIT, IDI, Provisión Pagos, etc.). Todos serán desplegados secuencialmente en la misma ejecución, dentro del ambiente seleccionado.
¿Cómo agrego un nuevo ambiente de pruebas?
Ve a Configuración → Ambientes → Nuevo ambiente. Ingresa el nombre del ambiente y agrega los sistemas con sus rutas de servidor. Solo los administradores pueden crear o modificar ambientes.
¿Dónde se guardan los datos de la aplicación?
Los usuarios e historial se almacenan en la base de datos SQL Server configurada en Configuración → General → Cadena de conexión SQL. La configuración de ambientes y sistemas se guarda como archivos JSON en la Ruta de configuración.
La aplicación no inicia — aparece un error al arrancar
  1. Verifica que .NET Framework 4.8 esté instalado en el equipo.
  2. Confirma que el servidor SQL Server esté activo y accesible desde tu red.
  3. Revisa que la cadena de conexión en App.config sea correcta.
  4. Comprueba que tienes permisos de lectura/escritura en la carpeta del ejecutable.
